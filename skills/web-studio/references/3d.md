# 3D and shaders

## Does 3D earn its place?
Use 3D when it shows something flat media can't: the product's form, a space you move through, a mechanism, scale, light over time. If the 3D could be replaced by a good photo with no loss, use the photo.

| Level | What | Cost |
|---|---|---|
| 0 None | Type, photo, video | — |
| 1 Ambient | Shader/gradient background, subtle particles | Low |
| 2 Hero object | One model, studio light, pointer + scroll camera | Medium |
| 3 Story scene | Camera choreographed through beats, multiple objects | High |
| 4 Explorable world | Free navigation, physics, game-like | Very high, needs plain-nav fallback |

## Setup (Next.js + React Three Fiber)
Packages: `three @react-three/fiber @react-three/drei` (+ `@react-three/postprocessing` only if the plan needs it, `@types/three` dev).

- The canvas lives in a client component; load it lazily so it never blocks first paint:
  `const Scene = dynamic(() => import("./scene"), { ssr: false, loading: () => <Poster /> })` (allowed only inside a `"use client"` file).
- Canvas baseline:
```tsx
<Canvas
  dpr={[1, 1.75]}
  camera={{ position: [0, 0, 6], fov: 35 }}
  gl={{ antialias: true, powerPreference: "high-performance" }}
>
  <PerformanceMonitor onDecline={() => setDpr(1)} onIncline={() => setDpr(1.75)} />
  <Suspense fallback={null}>
    <Model />
    <Environment files="/hdri/studio_small.hdr" />
  </Suspense>
</Canvas>
```
- Static or rarely changing scenes: `frameloop="demand"` and call `invalidate()` on change.
- Pause rendering when the canvas is off screen (IntersectionObserver → `frameloop` "never").

## Scroll-driven camera
Option A (GSAP owns scroll): ScrollTrigger writes progress into a ref; `useFrame` lerps camera/object toward the keyframe for that progress. Keeps one scroll system with Lenis.
```tsx
const progress = useRef(0);
useGSAP(() => {
  ScrollTrigger.create({ trigger: ".scene-track", start: "top top", end: "bottom bottom", scrub: true,
    onUpdate: (s) => { progress.current = s.progress; } });
});
useFrame((state, delta) => {
  const target = cameraPathAt(progress.current); // pure function of progress
  state.camera.position.lerp(target.position, 1 - Math.exp(-6 * delta));
  state.camera.lookAt(target.lookAt);
});
```
Option B (self-contained scene): drei `ScrollControls` + `useScroll()` inside the canvas. Simpler, but its own scroll container doesn't mix well with Lenis/ScrollTrigger pages.

Model-first rule (from the teardown method): write the scene as pure functions of one input (scroll progress, time, a slider). Every mesh, label and number reads from that model; nothing is animated by hand. This keeps parts, panels and camera from drifting apart.

## Assets pipeline
1. Source: Poly Haven (CC0 models/HDRIs/textures), ambientCG (CC0 materials), Kenney / Quaternius (CC0), Sketchfab CC0 filter, Poly Pizza (check CC-BY), client CAD/GLB. Record licence + attribution.
2. Optimise: `npx @gltf-transform/cli optimize in.glb out.glb --compress meshopt --texture-compress webp` (or inspect/tune at gltf.report). Budget: hero GLB ≤ 2–3 MB, textures ≤ 2K (1K on mobile).
3. Componentise: `npx gltfjsx out.glb --types` → typed JSX you can animate per mesh.
4. Decoders: Meshopt works out of the box with drei `useGLTF`; for Draco, self-host the decoder (`useGLTF.setDecoderPath("/draco/")`) instead of the default CDN.
5. HDRIs: 1K–2K `.hdr` from Poly Haven, self-hosted in `/public/hdri`.
6. Image-to-3D: the optional img2threejs skill can rebuild a reference object as procedural three.js code (see `resources.md`).

## Look and lighting
- Studio look: soft environment light + one key light, `ContactShadows` on an invisible floor, the object filling 60–70% of its view.
- Metal/plastic: `roughness` ≥ 0.45 avoids white streaks; glossy only where the design needs it.
- Light parts on light backgrounds: add a thin outline or darker ground so they don't vanish.
- Pick the camera for the subject: a 3/4 view when face-on collapses into a flat lattice.
- One accent colour for "the part that matters now".

## Shaders
- Ambient backgrounds: Paper Shaders (Apache-2.0, pin version) or ShaderGradient (MIT), or your own GLSL/TSL.
- Write your own shader code; Shadertoy / The Book of Shaders / Lygia are learning-only for client work.
- Render backgrounds at reduced resolution and scale up; cap to 30 fps if purely ambient.

## Post-processing
Each pass costs a full-screen draw. Budget: at most 2–3 cheap passes (Bloom, Vignette, Noise). SSAO/N8AO and depth of field only on desktop high tier. Disable all post on mobile and when `PerformanceMonitor` declines.

## WebGPU
three r187 ships `WebGPURenderer` + TSL with WebGL2 fallback. WebGPU is default on Chrome/Edge 113+ and iOS 26; desktop Safari 26 needs macOS 26; Firefox partial. Default to WebGL; use WebGPU only when a TSL effect needs it and the fallback is tested.

## Gotchas (where 3D usually breaks)
- **Raw ShaderMaterial output is linear**: sRGB textures are decoded to linear on sample, and a raw `ShaderMaterial` doesn't re-encode, so the result renders far too dark. Encode at the end (`pow(col, vec3(1.0/2.2))`) or use the renderer's colour-space chunks.
- **Texture colour spaces**: colour maps (day, albedo) are sRGB; data maps (specular, roughness, masks, ID maps) are linear/no colour space. ID/lookup maps also need nearest filtering and no mipmaps.
- **`smoothstep(edge0, edge1, x)` needs edge0 < edge1**: the reversed form happens to work in software GL but is undefined on real GPUs.
- **Screen → NDC**: `x = (px - left)/w * 2 - 1`, `y = -((py - top)/h * 2 - 1)`. A missing bracket silently sends rays off the object.
- **Picking many regions** (countries, units, plots): rasterise them once into an ID texture (one colour per region). The shader highlights by ID and the CPU reads the same pixels for names, so the two can never disagree. Antialiased edges create stray IDs: use a small majority vote around the sampled pixel.
- **Responsive camera**: pull the camera back on portrait screens so the hero object fits the width (distance from FOV and aspect), instead of letting it clip on phones.
- **Cap DPR** around 1.5–1.75; retina at full DPR costs far more than it shows.
- **Fixed backgrounds** (stars, skyboxes) belong to the scene root, not the rotating group, so they stay put while the object spins.
- **Dispose** geometries, materials, textures and canvases on unmount, and remove every listener.

## Performance tiers and fallbacks (required)
- **High** (desktop dGPU): full scene, post, DPR up to 1.75–2.
- **Medium** (integrated GPU laptops): DPR 1–1.25, no AO/DOF, smaller shadow maps.
- **Low** (mobile, weak GPU, `PerformanceMonitor` decline): DPR 1, no post, simplified materials, or swap to a poster/image sequence.
- **No WebGL / reduced motion**: static poster image with the same composition and alt text.
- Warm up shaders before the hero appears (render once offscreen or `gl.compile(scene, camera)`), so the first scroll never freezes.
- Test on a weak GPU: Playwright Chromium with CPU throttling (CDP `Emulation.setCPUThrottlingRate`) and sample FPS with `requestAnimationFrame` during a scripted scroll. Target ≥ 45 fps medium tier, 60 fps high tier.
